# Changelog

All notable changes to this project are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this
project adheres to semantic versioning.

## [Unreleased]

### Changed
- The menu is a side rail at the left (brand, the four pages with icons, the paused chip, the Light, Dark or Auto switch at the foot) instead of a top bar, and on a phone the same four pages are a tab bar fixed to the bottom edge with room for the home indicator. The page no longer stops at a fixed width: it fills the screen it is on, with a reading width kept only on Settings, Add folder and a folder's own page.
- The page you are on is marked clearly in the side rail: the current item is bold and filled, the others are dimmer, and hover only tints. Every page has its own heading and a tab title of the form `Page · Keepsake`; a folder's own page and Add folder keep Folders lit, the Locations page keeps Settings lit, and each sub-page has a "Back to ..." link above its heading. The Settings tabs use a filled, underlined look for the selected tab.
- The brand at the top of the side rail is the repository's own icon, inline (no extra request), beside a bolder wordmark with a lighter "for iCloud" under it on wide screens; the whole brand is one link to Folders (`aria-label` "Keepsake, Folders"). The tab icon is the same artwork: the SVG, a 32 px PNG (`/favicon-32.png`) and a 180 px touch icon (`/touch-icon.png`), served by the same static route.
- The MQTT status entities for the whole install are named "Problem", "Attention" and "iCloud Folder Confirmed": the device is already called Keepsake for iCloud, so their names no longer repeat it. The ids do not change.
- MQTT alerts no longer need the optional `paho-mqtt` package, which the container image never had, so the channel could not work there: they use a small client built on the standard library (`keepsake.mqttlite`), and the `mqtt` extra is gone from `pyproject.toml`.
- The Folders page is one card per folder in a grid that follows the screen: one column on a phone, more as the screen widens. A card shows the name and status, the nights, then the facts and the actions. Last run reads `12 added · 18s ago` (a failure is `Failed · 2h ago` with a short tag such as `source shrank`), Verified reads `✓ 40/40 · Tue 14:24` (`✗ 2 differ` in red, `Not checked`), Kept is a number only when something was kept, and the source path is shortened in the middle. The whole values, with the next check, are in each cell's title and in text for screen readers. Notes and errors under a row are one line that opens to the whole sentence. Sync is on the row and Preview, Check and Edit are in a “…” menu (arrow keys, Escape, Tab). A long text is cut with an ellipsis (its whole value is in the title) instead of widening the card. Times on the page are 24-hour (`Tue 14:24`) in every browser language.
- The Activity log is compact: one line per entry (time, a small dot, the folder, the message cut to one line, two on a phone), grouped by day with Today and Yesterday headings that fold away a day's routine lines and never its problems. Routine lines are quiet, problems keep their colour, and a line opens to its whole sentence and full time with Enter or a click. "All" and "Problems only" and a folder choice live in the address (`#/activity/problems/<folder>`), and "Show more" pages through the log, 50 at a time. What is recorded is unchanged.

### Added
- Live status over MQTT: with a broker and `KEEPSAKE_MQTT_DISCOVERY_PREFIX` set, Keepsake announces one device by MQTT discovery and keeps a retained status for every folder and for the whole install (the problem entity names which folders need a person), with a last-will offline message, publishing only what changed ([docs/api.md](docs/api.md#mqtt-status)).
- Progress for every long operation, one bar from one model: a first copy, a regular sync, a preview, "Check a copy" (and the scheduled check) and every restore report the phase in words, files and bytes so far, the folder they are in, the time they have run and when anything last happened, in `operation` and `progress_detail` on each job (`GET /api/status`, `GET /api/jobs/<name>`, `GET /api/jobs/<name>/preview`). The page shows a progress bar (`role=progressbar`, determinate when a total is known) in the wizard, on the Folders page, on a folder's page and on the deleted-files page, updated in place about every second while it shows and every five seconds otherwise; the last step of the wizard is two named stages ("Copying 1 of 2", "Checking 2 of 2") under one overall bar and starts the check by itself when the copy has finished. No news for 30 seconds is said plainly ("this is not an error yet"); after five minutes the page offers **Stop this run** (`POST /api/jobs/<name>/cancel`), which stops between files and blocks and leaves no half-written file and no change to your originals. A stopped copy is not an alarm.
- Change or reset the page password: Settings has a Change password form (`POST /api/password`: current password, the new one twice, at least 10 characters). The new password is stored as a salted scrypt hash in the data folder, replaces `KEEPSAKE_PASSWORD`, and signs every other browser out. If it is forgotten, `docker exec -it keepsake python3 -m keepsake reset-password` sets a new one and signs everyone out. A stored password counts as a password for the refuse-to-start rule.
- Add folder takes several folders at once: every folder row has a tick box (a ticked row is highlighted and checked) and a separate Open button, the chosen folders are listed with a count and survive moving into subfolders and between locations, and one "Add N folders" button creates them, one at a time, with a refusal for one never hiding the others.
- Several source folders go into ONE destination folder in iCloud Drive / Keepsake, each in its own subfolder named after it (two with the same name become `Holidays` and `Holidays-2`). A job gets an optional `group` (the destination folder) next to its `dest` (its subfolder). A single folder into a new destination is exactly as before. Every guard still runs per folder: the shrink guard, the 30-day `.deleted`, the anchor check, the owner marker and the run history. The destination is marked with `.keepsake-group`.
- Choose an EXISTING destination folder from a list of the folders already under iCloud Drive / Keepsake (`GET /api/destinations`), or type a new name. A folder Keepsake did not create is refused, at Add and again by the engine, until the person ticks the box that says to use it anyway; a folder that holds one folder's copy directly cannot also hold others.
- A Refresh button (icon, label, spinner and "Updated just now") on both the folder picker and the destination list: it reads the directory again, stays in the same folder and scroll position, keeps the chosen set, and says in a plain sentence when a chosen or current folder has gone.
- Locations can be added from the page: `GET /api/locations`, `POST /api/locations`, `POST /api/locations/<name>/remove` and `GET /api/locations/browse`, a Locations page (`#/locations`), an "Add location" button beside "Where is it?" and a self-contained `window.keepsake.locationsCard()` for other pages. The deployment mounts a broad parent folder read-only at a prefix (`/hostfs`, `KEEPSAKE_LOCATION_PREFIXES`), `KEEPSAKE_ROOTS` seeds the list and those entries are built in, and the rest are stored in `locations.json`. The server walks each choice without following symlinks and refuses anything outside a prefix, on a writable mount, overlapping the iCloud or data folder or another location, or reusing a name; a location a job uses cannot be removed and the refusal names the job.
- Names accept upper-case letters (Camel Case such as `PhotoLibrary`), keep their case on disk and in the API, and are unique whatever their case, so two names that differ only by case cannot collide on a Mac volume. The page shows them as readable Title Case (`Photo Library`) with the real name beside it.
- Guided setup that locks the rest of the page: a new install shows only a wizard (confirm the iCloud folder, where Keepsake may read from, choose folders and the destination folder, preview the first copy, make it and check it, done) from any address, with no menu, banner or link out and no way to skip a step. The step is read from the server (`setup` in `GET /api/status`: `complete`, `step`, `existing`), so a reload or another browser resumes it. The REST API answers only what the wizard needs and refuses everything else with 403 "finish the guided setup first: until it is done Keepsake only allows the setup steps" (an allow list in `server.setup_allows`, so a route added later is locked until it is named there); a folder that has not made a copy yet may still be removed. It is complete when the three first-run steps are true; an install that already has the confirmed iCloud folder and a folder when the service first starts is complete and never locked; once complete it stays complete (`setup.json` in the data folder). `docs/api.md`, the README and `docs/safety-model.md` describe it.
- Diagnostics you can attach to a bug report: `GET /api/diagnostics` (same login as the rest of `/api`) returns `keepsake-diagnostics.txt` as a download, and Settings has a "Download diagnostics" button. It holds the Keepsake and Python versions, platform, uptime, which alert channels are configured (names only), the schedule and pause state, each folder's last run, counts, iCloud state and last self-check, and the last 200 log lines from a bounded in-memory ring (`src/keepsake/diagnostics.py`). Built to leave secrets out: no password, token or address (URLs are cut to scheme and host, and anything after `token=`, `password=` or `Authorization:` is removed), the home folder shows as `~`, and no file names from inside your folders. `tests/test_diagnostics.py` proves it with a canary in every secret field.
- Release checksums: the release workflow builds a source tarball with `git archive` and attaches it to the GitHub release with a `SHA256SUMS` file.
- Guided first run: until the iCloud folder is confirmed, a folder exists, and a folder has finished a run and matched a copy check, the Folders page shows a three-step checklist (each step links to its page) instead of an empty table. The steps tick from real state, never from a flag, and the list goes away when all three are true. `first_run` on `GET /api/status` carries them.
- Preview next sync: `POST /api/jobs/<name>/preview` and `GET /api/jobs/<name>/preview`, a Preview button on every folder row and folder page, and a Preview offered inside the shrink-guard dialog. The engine plans a sync with the same guards and sentences as a real run, strictly read-only (it creates nothing in iCloud, writes no marker, removes no leftover temp file, and touches no manifest, state, history or activity log), on the worker queue one job at a time. The result (counts, up to 50 example files, which guard would refuse and why) is kept in memory and clearly labelled a preview. The planning half of a run moved into a function (`_plan_sync`) that both the run and the preview call.
- Per-night detail: each bar of a folder's Last 14 nights is now a button (arrow keys move along the strip) that opens that night's outcome, counts and up to 50 example files, as a bottom sheet on a phone. History entries carry an optional `detail`; older state files load unchanged and their nights say no detail was recorded.
- Pause everything: `pause` and `quiet_hours` in `PUT /api/settings`, and a Settings section with presets (1 hour, until tomorrow 08:00, 1 week), a date and time, Resume now, and a daily quiet window that may cross midnight. Scheduled syncs and checks do not start while it lasts, a running sync is never interrupted, Sync now and Preview still work, a pause and quiet hours are not counted towards the late-folder list or the stale alert, and the side rail shows a "Paused until" chip. Times follow `TZ`. `pause` is returned by `GET /api/status` and `GET /api/settings`.
- Run history: the service records one outcome per local day for each folder for the last 14 days (`copied`, `nothing`, `paused`; failed and refused runs are `paused`), written with the rest of the job state and returned as `history` on every job, with `today` on `GET /api/status`. Older state files load with an empty history.
- Check a copy: `POST /api/jobs/<name>/verify` and a button on every folder. It samples up to 40 files from the last run's manifest, reads each back from the source and from iCloud (never following links, never writing) and compares size and sha256. The result is stored per job and shown on the folder; a difference makes the folder need attention until a later check passes, and a check that could compare nothing is refused rather than reported as a match.
- Deleted files: `GET /api/jobs/<name>/deleted` and a page per folder listing what is under `.deleted/<date>/` with sizes and days left, and `POST /api/jobs/<name>/restore`, which copies one file into `.restored/<date>/` inside the folder's iCloud copy. The source is never written; `.restored` is a reserved folder the mirror ignores.
- What changed: each run records added, updated and moved-to-`.deleted` counts and up to 50 example paths, shown as a sentence on the folder and on the Activity page. The activity log keeps the counts only.
- A run is refused when the source's top level holds a name Keepsake keeps for itself in the iCloud folder (`.deleted`, `.removed`, `.restored`, `.keepsake-owner`).
- Optional macOS notifications: `tools/macos/keepsake-notify.sh` polls `GET /api/status` and posts a notification once when a folder newly needs attention and once when it leaves the attention list (also once when the API is unreachable, reachable again, or rejects the password); `install-notify.sh` and `uninstall-notify.sh` manage a per-user launch agent. See `docs/macos-notifications.md`.
- A release workflow (`.github/workflows/release.yml`) on `v*.*.*` tags: checks the tag against the version files and `CHANGELOG.md`, runs `make check` and `make docker-smoke`, creates the GitHub release from the changelog section, and pushes to GHCR only when the repository variable `PUBLISH_GHCR` is `true`. `scripts/release-notes.sh` extracts the section. Steps in `docs/releasing.md`.
- `docs/public-release-checklist.md`: what to verify before going public and while public.

- Honest iCloud state: each run counts the evicted placeholders (`.<name>.icloud`) it finds in the iCloud folder, returned as `icloud.evicted` and a plain `icloud.note` on every job, with a per-folder line on the Folders and folder pages saying what it means for a restore. A tested helper, `count_evicted`, reads it on demand. No macOS-only check (`brctl`, `xattr`) was added.
- Scheduled self-check: a per-folder setting "Check a copy automatically" (`auto_check`: off, daily, weekly, monthly). New folders default to weekly; folders stored before this stay off until set. The worker runs due checks one at a time and only when nothing is copying or queued. Checks now rotate through the manifest (a per-folder seed and cursor in the state file), so every file is looked at after about files / 40 checks; manual checks use the same rotation. A mismatch marks the folder "Needs attention" and sends the failed alert, a clean check records its time; the folder row shows the last and next check. `next_check`, `check_rounds` and `check_cycle_checks` are on every job.
- Alerts that reach you: ntfy, Pushover and e-mail (STARTTLS or SSL) next to the webhook and MQTT, all off unless configured through environment variables or `*_FILE` secret files and never shown by the API (Settings lists only whether each channel is configured). A "no successful run for N days" alert (`stale_days`, default 3, 0 = off, never sooner than twice the folder's schedule) fires once per outage, and the run that heals it sends a recovery message. `POST /api/settings/test-alert` and a "Send test alert" button report which channels worked and the plain error for each that did not. `stale` is a new `notify_on` event.
- Restore a whole date or everything kept: `GET /api/jobs/<name>/restore-plan` and `POST /api/jobs/<name>/restore-batch`, with "Restore all from this date" and "Restore everything kept" on the Deleted files page, which now groups by date and asks for confirmation with the count and size. Same guards as restoring one file, with the size cap and disk reserve checked for the whole batch before anything is written; links and unreadable entries are skipped and named.

### Changed
- The first-run help is now the Help tab of Settings (`#/settings/help`, remembered like the other tabs), in short sections: Getting started, Locations and folders, Destination folder, Copies and checks, Restore and deleted files, Alerts, Password, Troubleshooting. The standalone Help page and its "Read the first-run help" link are gone; the old `#/help` address redirects to the tab. While the guided setup is open the wizard is still the only page, so the Help tab is not reachable until the setup is finished.
- The Add folder form says "Destination folder" instead of "Name", with a line under it: "Copied into iCloud Drive / Keepsake / <name>."
- Settings is split into tabs (Limits, Alerts, Pause, Locations, Diagnostics, and Security when the page has a password) with a keyboard-operable tab bar (arrow keys, Home and End). The open tab is in the address (`#/settings/alerts`) and comes back on reload; links that point at one thing open its tab (the iCloud confirmation opens Locations, the paused chip opens Pause). Edits you have not saved stay while you switch tabs or press a button that redraws the page, the page says which tab has them, and one Save settings saves Limits and Alerts together. On a phone the bar scrolls inside itself. No setting, API field or id changed.
- While the guided setup is open a new folder's first copy does not start by itself: the wizard shows the preview and then starts it. Once the setup is complete nothing changes, and a new folder's first copy still starts at once.
- The night bars are buttons with an accessible name such as "Nov 6: copied, 12 added"; the Folders page keeps keyboard focus on the same control when it redraws.
- A dialog's answer is cleared each time it opens, so an earlier "yes" is never read as the answer to a later dialog. (Chromium already clears it when Escape closes a dialog; this makes it independent of the browser.)
- `PUT /api/settings` rebuilds the alert channels only when the webhook or the alert events are in the request.
- `next_run` and `next_check` on a job are never earlier than the time scheduled work may start again.
- The demo server used for screenshots and the UI test runs what a person asks for (Sync now, Preview) and takes `--no-jobs`, `--pause` and `--live-worker`.
- `GET /api/status` `note` and the Help text no longer imply the copy is "in iCloud" once a run finishes.
- Dialogs open from the button that opened them and go back the same way; a copying folder shows a quiet progress bar and the button answers at once. Sheets, toasts and the phone top bar use a translucent material, with solid fallbacks for reduced transparency and a stronger-contrast mode. Text follows the browser's text size.
- A new console look replaces the earlier side rail and cards: a top bar (Folders, Activity, Deleted files, Settings) and one Folders table with a status pill, a strip of the last 14 nights, last run, verified and kept counts, and Sync, Check and Edit actions (Review after a shrink refusal). On a phone the rows stack. The Cards/Table switch is gone, and the table no longer shows the next run or size per folder (the summary line shows the next sync). Deleted files is a top-bar page that lists the folders; Add folder is a button on Folders and Help is linked from Settings.
- A Light, Dark or Auto switch in the top bar replaces the single Theme button; the choice is saved in the browser and applied before the page paints.

### Removed
- The sentence saying Keepsake confirms what is in the iCloud folder on this Mac, not what Apple has uploaded, with its advice to check the iCloud status in Finder: from the Folders page, the folder settings, the first-run list, the wizard, Help, the README and the docs. `GET /api/status` no longer carries the top-level `note` field that held only that sentence. The evicted-placeholder count (`icloud.evicted`, `icloud.note`) and what it means for a restore are unchanged.

### Added
- The sync engine: one-way mirror into iCloud Drive with `.deleted` retention,
  size caps, free-disk reserve, shrink guard (files, bytes, paths), safe first
  run, ownership and anchor markers, no symlink following, mount-is-real proof,
  evicted-placeholder handling.
- A built-in web page (Folders, Add folder with a folder picker, Folder
  settings, Activity, Settings, Help; light and dark, no external requests) and
  a REST API.
- Password required for any non-loopback address, CSRF protection, rate-limited
  login, security headers.
- Optional webhook and MQTT notifiers.
- Docker image (pinned Alpine base, non-root, read-only root, health check) and
  compose file.

### Fixed
- The guided setup could keep saying "Reading" after the server had finished: the page skipped every redraw while it believed a key was held, and a key-up that never arrives (a screenshot shortcut, Cmd-Tab) kept that belief for ever. It now expires after two seconds and is cleared when the window loses focus. "Reading" is only ever what the server says (previewing, queued or running); an idle server with no result shows "The preview did not start. Try again." with a Retry button. A preview or copy that fails outside the engine now ends in a stored sentence, and the worker frees the folder, instead of leaving it marked as busy.
- The Folders page and the wizard no longer redraw while the person has just done something (focused a control, pressed a key or a button) and the Folders page only redraws when something a person can see has changed, so a redraw cannot swallow the next keypress. Progress bars are updated in place instead.
